# limit_mistake_finder

Tampermonkey-скрипт **TH Management — Limit Mistake Finder** (`limit-mistake-finder.user.js`).

Проходит **все страницы** текущего фильтра на `paymentsupport` и `ExtendedPaymentRequestList`, берёт тикеты в статусах **Credited (M)**, **Credited (Fraud) (M)** и **Closed (M)**, у которых **транзакция в статусе OK**, и сравнивает **Amount by receipt** (поле `amount`) с лимитами их **метода** со страницы Confluence «ЛИМИТЫ РУЧНЫЕ» с учётом страны. Тикеты ниже или выше лимита показываются списком, и их можно скачать в Excel.

## Установка
1. Установить расширение Tampermonkey.
2. Открыть ссылку **https://raw.githubusercontent.com/partenkoEgor/limit_mistake_finder/main/limit-mistake-finder.user.js** — Tampermonkey сам предложит установить скрипт, нажать «Установить».
3. Залогиниться в Confluence (`doc.office.lan`) в этом же браузере: скрипт загружает страницу лимитов с вашими куками.
4. При первом запросе к `doc.office.lan` Tampermonkey спросит разрешение — нажать «Always allow domain».

Обновления приходят автоматически (Tampermonkey проверяет `@updateURL`), вручную — «Проверить обновления» в меню Tampermonkey.

## Как пользоваться
1. Открыть List of payment queries (или Extended) и задать фильтр. Чтобы проверка шла быстрее, можно сразу отфильтровать по нужным статусам (Credited (M), Credited (Fraud) (M), Closed (M)).
2. Нажать **APPLY**: скрипт перехватит запрос списка (в панели появится «✅ Фильтр пойман»).
3. Открыть панель кнопкой **Limits** справа внизу (или Alt+L) → **▶ Проверить все страницы**.
4. Результаты на вкладках:
   - **Ниже лимита** / **Выше лимита** — Ticket ID (клик копирует), Method / Subagent, сумма, Min, Max, отклонение, строка Confluence и её страна. Пометка «⚠ страна не совпала» значит, что метод нашёлся только в таблице другой страны, а «⚠ проект не совпал» — что для проекта тикета (nameRef) своей строки нет и взята строка другого проекта;
   - **Не удалось проверить** — метода нет в Confluence, лимит в Confluence не распознан, лимит указан в другой валюте, найдено несколько строк с разными лимитами (например, метод есть в нескольких странах, а страна тикета ни с одной не совпала) или не читается сумма. Причина указана в строке.
   - тикеты, у которых транзакция **не в статусе OK** (Pending, Rejected или транзакции нет), не проверяются: зачисления не было. Их число видно в плитке «Транзакция не OK» и в «Сводке» (с разбивкой по статусам);
   - **Проверить вручную** — сумма в лимите, но лимит взят из строки другой страны или другого проекта, поэтому результату нельзя полностью доверять. Причина указана в строке.
5. **⬇ Скачать Excel**: в файле листы «Ниже лимита», «Выше лимита», «Не удалось проверить», «Проверить вручную» и «Сводка» (по методам и странам, плюс итоги обхода).

## Как ищется лимит
1. Берётся `method` тикета (например, ` Sham Cash SYP`), затем он же без кода валюты (`Sham Cash`), затем `Subagent` как запасной вариант. **Если Subagent прямо называет метод из Confluence** («Arcturus **CLIQ** Jordan» → «Cliq»), а method указывает на другую строку («Bank al Etihad») — важнее Subagent; это отмечается в колонке «Примечание».
2. Совпадение с колонкой «Метод» в Confluence: точное (в том числе без бренда в скобках: «ATTIJARI (1XCasino)» → «ATTIJARI») → без пробелов и апострофов («L'bankalik» = «Lbankalik») → вхождение целыми словами. При вхождении выигрывает самое длинное название: `Cash Plus` важнее, чем `Cash`.
3. **Страна:** `nameCountry` тикета (Syria, Kyrgyzstan…) сверяется с колонкой «Страна» и заголовком таблицы (Сирия, Киргизия…). Словарь стран — `COUNTRY_ALIASES` в скрипте. Таблицы, страну которых скрипт не узнал, перечислены в «Диагностике».
4. **Проект (бренд):** по `nameRef`/`refId` тикета выбирается строка своего проекта. Проект строки определяется по **заголовку таблицы** («Египет 1XCasino», «Турция Melbet BT», «Марокко BizBet Africa (Ar) 365», «…расшарены с рефки 1 на 292»), по бренду в скобках и по «Переключалке»; таблица с одним названием страны — webDefault:
   - для `webDefault` (и зеркал 1xbet: `1xbet22.com`, `bo.1xbet.com`…) — строки не из таблиц проектов, приоритет у строк с `webdefault` / `default` в «Переключалке»;
   - для других проектов — строки с названием проекта в скобках или с его `refId` в «Переключалке» (`…_bt_292_…`). Если у проекта **нет своей таблицы для страны** (например, 1xCasino в Бахрейне, Иордании, KSA), действуют лимиты webDefault — это считается верным, в «Примечании» пишется «лимиты webDefault». Если таблица проекта для страны есть, а нужного метода в ней нет, берётся строка webDefault с пометкой «проект не совпал» (при сумме в лимите — «Проверить вручную»).
   
   Список брендов — `CONFIG.knownBrands`, к нему автоматически добавляется всё, что встречается в скобках 2+ раз.
5. **Списки субов** — колонка «Субы» или блок «Агенты: 19902 (Huskar D17 Tunisia) …» в любой ячейке строки, когда для метода осталось несколько строк с разными лимитами:
   - если Subagent тикета указан в блоке «исключения по лимитам (500-30000 KGS): …» — берётся лимит из заголовка этого блока;
   - иначе берётся строка, в списке «Субы» которой есть Subagent тикета (по имени, номер в конце не обязателен, или по ID субагента).
   
   - если суба нет ни в одном списке, а есть строка без списка, берётся она — с примечанием, и при сумме в лимите тикет попадает в «Проверить вручную»;
   - до этого работает правило **отличительных слов**: если строки одного метода различаются словами («D17 **QR-code** Tunisia» / «D17 Tunisia»), берётся строка, чьё отличительное слово есть в method/Subagent тикета, а если таких слов в тикете нет — строка без них (обычный D17). Названия брендов здесь не участвуют — проект выбирается по своим правилам;
   - строка вида «Astara Azerbaijan BirBank 53968» (номер суба в названии) относится только к этому субу.
   
   Если строк всё ещё несколько, остаётся та, в названии которой есть слово из Subagent тикета («Anamudi Azerbaijan BirBank» → «Bank köçürməsi - BirBank»). Строка без распознанного лимита («лимиты в строчке ниже») не выигрывает у строки с лимитом. Названия сравниваются без диакритики («Hızlı» = «Hizli», «YapıKredi» = «YapiKredi»).
   
   Всё читается из Confluence при каждой загрузке, в скрипте ничего не зашито.
6. **Валюта.** Если подходят строки с разной валютой (например, «Sham Cash SYP» / «Sham Cash USD»), выбирается строка с валютой тикета. Если найдена строка с лимитом в другой валюте, а в той же таблице есть такая же строка в валюте тикета, берётся она: тикет в LBP по «Whish» (лимит в USD) сверяется со строкой «Whish LBP». Если лимит указан в другой валюте, а строки в валюте тикета нет, суммы не сравниваются: тикет попадает в «Не удалось проверить» с причиной «лимит в USD, тикет в LBP».
7. **Несколько строк с разными лимитами** (например, одинаковый метод в таблицах «Турция Melbet BT» и «Турция Melbet API»): если сумма даёт один результат по каждой строке, он и засчитывается. Если сумма в лимите везде, тикет считается проверенным. Если нарушение по каждой строке, тикет попадает в «Ниже»/«Выше» с самой мягкой границей (наименьший min / наибольший max). Список строк виден в «Примечании». Только если по одной строке сумма в лимите, а по другой нет, тикет остаётся в «Не удалось проверить».
8. В ячейке «DEPOSIT LIMITS … WITHDRAWAL …» берётся только раздел депозита.
9. Зачёркнутые строки используются, только если других нет.

## Первый запуск — «🩺 Диагностика»
Ключи JSON списка и формат таблицы в Confluence скрипт определяет автоматически:
- ключи полей берутся из **таблицы на экране**: значения колонок Subagent / External Status / Country сверяются с ответом сервера. Если так не получилось, поля ищутся по названию ключа;
- в Confluence шапка таблицы («Метод | Лимиты | Переключалка | Страна | Доп.информация/Настройки») распознаётся, даже если она сделана из обычных ячеек. Лимиты берутся из колонки «Лимиты» (или Min/Max, От/До) из текста вида `100 - 5 000`, `от 100 до 5000`, `Мин: 100 Макс: 5000`.

«Диагностика» показывает:
- какие ключи выбраны (с примерами значений);
- как разобрались таблицы Confluence: что распознано, а что нет;
- **проверку сопоставления**: для тикетов нужных статусов со стр. 1 видно, в какую строку Confluence попал каждый тикет, с какими min/max и с каким вердиктом;
- все ключи первой строки ответа.

## Настройки (блок `CONFIG` в начале скрипта)
- `statuses` — какие статусы проверять (по умолчанию `['Credited (M)', 'Credited (Fraud) (M)', 'Closed (M)']`).
- `txnStatuses` — при каком статусе транзакции (поле `transactionStatusName`) тикет проверяется, по умолчанию `['OK']`; `[]` — не фильтровать по транзакции. Если поле в ответе не найдено, проверяются все тикеты, а «Диагностика» об этом предупредит.
- `fields` — явно задать ключ JSON. По умолчанию `amount: 'amount'` (Amount by receipt); для суммы транзакции было бы `'summa'`.
- `knownBrands` — список брендов/проектов для выбора строки по `nameRef`.
- `limitOverrides` — ручные лимиты, они важнее Confluence; ключ — method или subagent: `'Sham Cash SYP': { min: 100, max: 30000 }`.
- `limitsPageUrl` — адрес страницы лимитов.
- `pageDelay`, `pageRetries`, `pollInterval`, `pollMax` — темп обхода страниц и повторы при ошибках.
